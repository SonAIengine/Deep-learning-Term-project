# Part I — 빌딩블록: Transformer가 안에서 실제로 하는 일

> 이 연구를 이해하려면 "attention head가 뭘 하는 부품인지"를 알아야 한다. 그게 이 Part의 전부다.

## §1. 토큰에서 출력까지 — 전체 파이프라인

GPT-2 같은 decoder-only Transformer가 `"x=5; z=9; a=z; a="`를 받아 `9`를 뱉기까지:

```
텍스트 → [토큰화] → 토큰 ID 열 → [임베딩] → 벡터 열
        → [Layer 0] → [Layer 1] → ... → [Layer 11]   (각 Layer = Attention + MLP)
        → [최종 LayerNorm] → [Unembedding] → 어휘 전체에 대한 logit → softmax → 다음 토큰
```

- **토큰화(BPE)**: 텍스트를 조각(token)으로 쪼갠다. GPT-2는 BPE(Byte-Pair Encoding — 자주 같이 나오는 글자쌍을 한 토큰으로 묶는 방식)를 쓴다. `" 9"`는 한 토큰이지만 `" 13"`은 `" 1"`,`"3"` 두 토큰으로 쪼개진다. **(이게 나중에 "정답을 1~9로 제한한 이유" — §14)**
- **임베딩**: 각 토큰 ID → `d_model`차원 벡터(GPT-2 small은 768차원), 행렬 `W_E`로 변환. 여기에 **위치 임베딩(positional embedding)** 을 더한다 — attention 자체는 순서 개념이 없어서(아래 보충), "이 토큰이 몇 번째인지"를 벡터로 주입해야 어순을 안다.
- **Layer 반복**: 각 층은 두 부품 — **Attention**(토큰끼리 정보 교환)과 **MLP**(토큰별 비선형 변환). GPT-2 small은 12층.
- **Unembedding**: 마지막 벡터를 `W_U`로 곱해 어휘 크기(50257)만큼의 점수(logit)를 낸다. 가장 높은 게 예측 토큰.

> **핵심 직관**: 모델의 "생각"은 이 파이프라인을 흐르는 **벡터**에 담겨 있고, 회로 분석은 그 벡터가 **어디서 어떻게 바뀌는지** 추적하는 일이다.

### §1 보충 — 꼭 알아야 할 5개념 (질문 단골)
- **Causal attention (왜 '다음' 토큰만 예측?)**: GPT-2는 **decoder-only**라서, 각 토큰은 **자기보다 앞쪽 토큰만** 볼 수 있다(미래는 마스킹). 그래서 "다음 토큰 예측"으로 학습/추론한다. IOI·코드 과제에서 정답을 **맨 끝 위치(final position)** 의 logit에서 읽는 이유 — 거기서만 문장 전체를 다 봤기 때문.
- **MLP의 역할**: attention이 "토큰 사이 정보 이동"이라면, MLP는 "한 토큰 안에서의 비선형 변환·지식 조회"다. 흔히 **key-value memory**(입력 패턴→저장된 사실)로 본다. grokking에서 핵심 회로가 L1 MLP에 몰린 게 그 예(§15).
- **softmax**: logit(점수)을 확률로 바꾸는 함수. `P(토큰) = exp(logit) / Σexp(logit)`. 우리는 확률 대신 **logit 자체**를 분석한다(§6, 선형이라 분해가 쉬움).
- **cross-entropy loss**: 학습 목표. 정답 토큰의 예측 확률이 높아지도록 `−log P(정답)`을 최소화한다. grokking의 "train loss→0, test loss 늦게→0"이 이 값.
- **logit이 분해 가능한 이유**: residual stream(§2)이 선형 누적 + unembedding이 선형이라, 최종 logit = 각 부품 기여의 **합**. → patching·attribution이 성립하는 토대.

## §2. Residual Stream — 정보의 고속도로 (가장 중요한 개념)

Transformer를 이해하는 핵심 관점(Elhage et al. 2021, "A Mathematical Framework"):

> 각 토큰 위치마다 **residual stream(잔차 스트림)** 이라는 벡터가 하나씩 흐른다. 모든 부품(attention head, MLP)은 이 스트림을 **읽고(read)**, 계산해서, 결과를 다시 **더한다(write/add)**.

```
residual stream (위치 t):  x₀ ──+h1──+h2──+mlp──+...──→ x_final → unembed
                                 ↑    ↑    ↑
                          각 부품이 자기 출력을 "더한다"
```

- 핵심은 **덧셈**이다. 부품들은 스트림을 덮어쓰지 않고 **누적**한다. 그래서 최종 logit은 "모든 부품이 정답 방향에 기여한 양의 합"으로 분해할 수 있다 → 이게 **Direct Logit Attribution**(§9)의 수학적 근거.
- 비유: residual stream은 **컨베이어 벨트**, 각 head/MLP는 벨트 옆에서 물건을 보고 새 물건을 **얹는** 일꾼. 누가 무엇을 얹었는지 추적하면 최종 결과를 설명할 수 있다.
- **왜 이게 중요한가**: 회로 분석이 가능한 근본 이유. 부품들이 선형적으로(덧셈으로) 합쳐지기 때문에, 특정 부품의 기여를 분리(patching)하거나 정답 방향 투영(attribution)이 의미를 가진다.

## §3. Attention Head — 두 개의 독립 회로 (QK와 OV)

한 attention head가 하는 일은 두 질문으로 쪼개진다 (Elhage 2021의 핵심 통찰):

**① QK circuit — "어디를 볼까?" (attention pattern)**
- 각 토큰은 **query** 벡터를, 각 토큰은 **key** 벡터를 만든다.
- query·key 내적이 크면 "그 토큰에 주목". softmax로 정규화 → **attention 패턴**(각 위치가 다른 위치에 얼마나 주목하는지).
- 수식: `attention[i→j] = softmax_j( (x_i W_Q)(x_j W_K)ᵀ / √d )`

**② OV circuit — "무엇을 가져올까?" (정보 이동)**
- 주목한 토큰의 **value** 벡터를 가져와, `W_O`로 변환해 **자기 위치의 residual stream에 더한다**.
- 수식: head 출력 = `Σ_j attention[i→j] · (x_j W_V) W_O`

> **핵심**: QK는 "**누구를** 볼지", OV는 "**무엇을** 그 자리로 옮길지"를 독립적으로 결정한다. 이 둘의 조합이 head의 기능을 정의한다.

**예시로 감 잡기 — "Previous Token Head"**:
- QK: 항상 **바로 앞 토큰**에 주목 (위치 i가 i-1을 봄)
- OV: 앞 토큰의 정체를 복사
- → 결과: "직전 토큰을 다음 자리로 복사하는" 기능 단위. 이게 head 하나가 하는 **명확한 알고리즘적 역할**.

**"L10H7" 표기**: Layer 10의 7번 Head. GPT-2 small = 12층 × 12head = **144개 head**.

## §4. 왜 attention head가 "기능 단위"인가

- 각 head는 자기만의 `W_Q, W_K, W_V, W_O`를 가진 **독립 계산 단위**. 서로 직접 간섭하지 않고 residual stream을 통해서만 소통.
- 그래서 "이 head는 중복 토큰을 탐지한다", "저 head는 정답을 출력으로 옮긴다" 식으로 **개별 역할을 부여**할 수 있다.
- circuit(회로) = 이런 head들이 residual stream을 통해 정보를 **릴레이**하며 하나의 과제를 푸는 배선도.
- **이 연구가 묻는 것**: 영어 과제를 푸는 head 배선도와 코드 과제를 푸는 배선도가 **같은 head들**로 이뤄졌는가?

# Part II — 해부 도구: Mechanistic Interpretability 방법론

## §5. 왜 회로를 들여다보나 (분야의 동기)

- LLM은 입출력은 잘하지만 **내부 계산은 블랙박스**. "왜 이 답을 냈는지" 보장할 수 없다 → 안전·신뢰 문제.
- **Mechanistic Interpretability(MI)**: 블랙박스를 열어 내부 head·뉴런이 **실제로 어떤 알고리즘**을 돌리는지 회로 수준으로 규명.
- 비유: 뇌 전체를 fMRI로 흐릿하게 보는 게 아니라, **뉴런 하나에 전극을 꽂아 "이건 얼굴 인식 뉴런"** 이라 특정하는 것.
- 발표 멘트(권위 부여): MI는 2026 MIT Tech Review 주목 분야, Anthropic이 회사 핵심 목표로 선언한 영역.

## §6. logit, logit difference, logit lens

**logit**: unembedding 직후 각 어휘 토큰이 받는 **점수**(아직 softmax 전). 높을수록 모델이 그 토큰을 선호.

**logit difference (logit_diff)** — 이 연구의 주력 평가 지표:
```
logit_diff = logit(정답 토큰) − mean(logit(방해답 토큰))
=> 모델이 정답을 얼마나 자신 있게 고르는가"를 수치로 나타낸 것
```
- IOI: `logit("Mary") − logit("John")`
- 코드: `logit(" 9") − logit(" 5")`
- **왜 정확도가 아니라 이걸 쓰나?** (자주 받는 질문) 코드 과제에서 Top-1 정확도는 0.8%로 매우 낮다. 모델이 최종적으로 엉뚱한 토큰을 1등으로 뽑더라도, **정답 쪽으로 기우는 미세한 신호**는 logit_diff에 잡힌다. 회로의 인과적 기여를 재는 데는 연속적인 logit_diff가 0/1 정확도보다 훨씬 민감하고 적합하다.

**logit lens / direct attribution의 토대**: residual stream이 선형 누적(§2)이므로, 최종 logit_diff = 각 부품이 "정답 방향"에 기여한 양의 **합**으로 분해된다.

## §7. Activation Patching — 주력 해부 기법 ★★★

**목표**: "이 head가 정답에 **인과적으로** 중요한가?"를 측정. (단순 상관이 아니라 인과)

**절차**:
1. 모델을 **두 번** 실행한다.
   - **clean run**: 정답이 나오는 입력. `a=3; b=5; c=a; c=` → 정답 **3**
   - **corrupt run**: 정답이 바뀌도록 최소 변형한 입력. `a=3; b=5; c=b; c=` → 정답 **5**
2. clean run을 돌릴 때 모든 head의 출력(activation)을 **저장**해 둔다.
3. corrupt run을 돌리되, **조사 대상 head 하나의 출력만** clean run에서 저장한 값으로 **바꿔치기(이식)** 한다.
4. 그 결과 logit_diff가 corrupt 쪽에서 clean 쪽으로 얼마나 **돌아오는지(recovery)** 측정.

> **직관**: 고장난 기계(corrupt)에 정상 부품(clean) 하나만 꽂아본다. 그 부품 하나로 기계가 되살아나면 → 그 부품이 핵심. 안 살아나면 → 안 중요.

**무엇을 패치하나**: 이 연구는 각 head의 출력 `blocks.{L}.attn.hook_z`(OV circuit 출력)를 패치. 144개 head를 **하나씩 전부**(per-head sweep) 돌려 각각의 recovery를 잰다.

**왜 강력한가**: ablation(끄기)은 "없으면 망가지나"만 보지만, patching은 "**정상값을 주입하면 복원되나**"라 더 직접적인 인과 증거. correlation이 아니라 intervention(개입).

**핵심질문**: 이 head가 진짜로 중요한 건지, 아니면 그냥 우연히 같이 활성화되는 건지 어떻게 구별하나?
MLP 단위로도 할 수 있고, 특정 레이어의 MLP 전체,
또는 MLP 내부의 뉴런 하나하나도 가능하다.
레이어(Layer) 전체를 통째로 교체할 수도 있다.
Attention + MLP 합쳐친 레이어 전체를 clean 값으로 바꾸는 식. 
Residual stream 도 대상이 된다. 트랜스포머는 레이어들이 residual stream 이라는 공유 채널에 값을 더해가는 구조인데, 특정 위치(토큰)의 특정 레이어에서의 residual stream 값을 통째로 교체할 수 있다. 토큰 위치도 변수이다.

## §8. Counterfactual Pair — 왜 clean/corrupt를 한 토큰만 다르게? ★★

Activation patching이 깨끗하게 작동하려면 clean과 corrupt가 **딱 한 요소만 다른 minimal pair**여야 한다.

```
Clean:      "a=3; b=5; c=a; c="   → 정답 3
Corrupt:    "a=3; b=5; c=b; c="   → 정답 5
                       ↑
              source 변수명 한 토큰만 swap (a↔b)
```

- **왜?** 두 입력이 여러 군데 다르면, 패치로 logit_diff가 변해도 "어느 차이 때문인지" 분리 불가. 단 한 토큰만 다르면 **그 한 군데의 정보 흐름**만 깔끔하게 추적된다.
- Wang 2022가 IOI에서 ABBA/BABA 패턴을 통제한 것과 동일한 발상.
- **왜 single-token 변수명?** clean·corrupt의 토큰 위치가 **1:1 정렬**돼야 패치가 의미 있다. 변수명이 서로 다른 개수의 토큰으로 쪼개지면 position이 어긋나 분석 불가. 그래서 `a,b,c,x,y,z`처럼 한 토큰으로 인코딩되는 이름만 사용.

## §9. Direct Logit Attribution — 부호(±)까지 재는 도구 ★★

Patching은 "중요하다"까지만 말한다. 이 head가 정답을 **밀어주는지(+) 깎는지(−)** 는 따로 봐야 한다.

- residual stream이 선형 누적(§2)이므로, 각 head 출력을 **정답 방향**에 직접 투영하면 그 head의 logit_diff 기여를 부호까지 얻는다.
- 정답 방향 = `W_U[정답] − mean(W_U[방해답])`.
- head 기여 = `(head의 최종위치 출력) · (정답 방향)`. 양수면 정답 강화, 음수면 정답 억제.
- **이게 만든 결정적 결과**(§20): NNMH 계열 head가 코드에서도 **음수**(정답을 깎음) → 역할의 부호까지 전이됐다는 증거.

> **z-score란?** (§20에 `z=+3.3`, `z=−1.9`로 등장) 어떤 head의 기여가 *나머지 head들에 비해 얼마나 튀는지*를 표준편차 단위로 잰 값. `z = (그 head 기여 − 전체 평균) / 표준편차`. |z|>2면 우연이 아니라 통계적으로 두드러진다는 뜻. L10H2의 z=+3.3 = "정답 강화가 매우 유의하게 두드러짐", L10H7의 z=−1.9 = "정답 억제가 두드러짐". 즉 부호 보존이 노이즈가 아니라는 근거.

## §10. Ablation — 제거 실험

- 대상 head 출력을 **0으로** 만들고 성능 변화 측정.
- "이 head가 없으면 얼마나 망가지나" = **necessity(필요성)** 측정.
- 회로 크기 측정(§21)과 hydra effect 발견(§23)에 사용.
- 한계: 큰 모델에선 백업 head가 대신 일해서(redundancy) ablation만으론 오해석 위험 → §23.

## §11. recovery 지표 — 수식과 해석 ★

```
recovery = (패치 후 logit_diff − corrupt logit_diff) / (clean logit_diff − corrupt logit_diff)
```

- 분모 = clean과 corrupt의 logit_diff 격차(= 그 입력 변화가 만든 전체 효과).
- 분자 = 그 head 하나를 패치해서 회복된 양.
- **recovery = 1**: 그 head 하나로 정답 신호 **완전 복원**.
- **recovery = 0**: 효과 없음.
- **recovery < 0(음수)**: 패치하면 오히려 정답에서 **멀어짐** (그 head는 정답을 방해하는 방향). ← SIH가 음수인 게 이 경우(§19).

# Part III — 두 과제와 IOI 회로

## §12. IOI 과제 (Indirect Object Identification)

- 입력: *"Mary and John went to the store. John gave a drink to ___"*
- 정답: **Mary** (방해답: John)
- 구조: 두 이름(entity)이 등장하고, 한 명(John)이 반복(주어로). 모델은 **반복되지 않은 쪽(Mary)** 을 간접목적어로 예측해야 한다.
- **왜 표준 벤치마크인가**: Wang et al. 2022가 GPT-2 small에서 이 회로를 **완전히 해부**해 26개 head, 7개 역할로 정리해 놓았다. 정답지가 있으니 다른 과제의 head를 여기에 **직접 대응**시킬 수 있다.

## §13. IOI 26 head, 7가지 역할 — 정보 흐름으로 해부 ★★★

IOI 회로는 입력→중간→출력 단계로 정보를 릴레이한다. 각 역할이 무슨 일을 하는지:

| 약어 | 풀네임 | 하는 일 | 단계 | 전이? |
|---|---|---|---|---|
| **DTH** | Duplicate Token Head | "John이 두 번 나왔네" 중복 토큰 탐지 | 입력 | 부분 |
| **PTH** | Previous Token Head | 직전 토큰 정보를 다음으로 복사 | 입력 | X |
| **IH** | Induction Head | 반복 패턴(A...A→) 탐지·이어쓰기 | 중간 | X |
| **SIH** | S-Inhibition Head | 중복된 이름(John)을 **억제**해 후보에서 빼기 | **구조** | **X (핵심)** |
| **NMH** | Name Mover Head | 살아남은 정답(Mary)을 **출력 위치로 이동** | **출력** | **O** |
| **BNMH** | Backup Name Mover | NMH가 죽으면 **대신 일하는 백업** | 출력 | O |
| **NNMH** | Negative Name Mover | 정답 logit을 **일부러 깎는** (과신 방지) | 출력 | **O (부호까지)** |

**정보 흐름 스토리**:
1. DTH/PTH/IH가 입력에서 "어느 이름이 중복인지" 신호를 만든다.
2. **SIH**가 그 신호를 받아 중복된 John을 **억제** → 정답 후보를 Mary로 좁힌다. (이게 IOI의 핵심 "구조" 연산)
3. **NMH**가 좁혀진 Mary를 출력 자리로 옮겨 logit을 올린다.
4. **NNMH**는 반대로 살짝 깎아 균형을 맞춘다(모델의 calibration).

> **이 연구의 핵심 발견 미리보기**: 코드 과제에선 **3·4번(출력: NMH/BNMH/NNMH)은 그대로 재사용**되지만, **2번(SIH)은 안 쓰인다**. 왜? 코드 `x=5; z=9; a=z`엔 "같은 이름이 두 번 나와서 하나를 억제해야 하는" 중복 구조가 **없기 때문**. SIH가 할 일 자체가 없다. → "선택적 재사용"(§18).

> **참고: Induction Head란?** (MI에서 가장 유명한 회로 부품 — 질문 단골) "`A B ... A` 다음엔 `B`"라는 **in-context 반복 패턴**을 학습한다(예: 'Harry Potter'가 한 번 나오면, 다음 'Harry' 뒤에 'Potter' 예측). Previous-Token Head가 만든 정보를 Induction Head가 조회하는 2-head 협업으로 작동하며, LLM의 **in-context learning** 능력의 핵심으로 알려졌다(Olsson 2022). 본 연구에선 코드 binding에 이 반복 구조가 약해 전이가 거의 없다(§18, IH 평균 −0.012).

## §14. Variable Binding 과제와 데이터 설계 철학

**과제**: `x=5; z=9; a=z; a=` → **9**. 두 변수(x,z) 중 binding(`a=z`)으로 정답값을 추적.

**IOI와의 구조적 대응**:
| 항목 | IOI | 코드 binding |
|---|---|---|
| 후보 | Mary, John | 5, 9 |
| 정답 선택 기준 | binding 관계 | binding 관계(`a=z`) |
| 방해 요소 | 반복 entity(John) | 다른 변수 값(5) |

**데이터 설계의 5가지 "왜" (datasets.md v2 — 질문 방어 필수)**:

1. **왜 counterfactual pair?** (§8) → patching 신호를 깨끗하게. clean/corrupt가 source 변수 한 토큰만 다름.
2. **왜 single-token 변수명?** → clean·corrupt 토큰 위치 1:1 정렬 보장. `a,b,c,x,y,z`만 사용.
3. **왜 정답값 1~9?** → GPT-2 BPE에서 `" 0"`~`" 9"`만 single token. 두 자리 수는 쪼개져서 정답 logit을 한 토큰에서 직접 읽을 수 없음.
4. **왜 1-hop이 기본?** → 비교 대상 IOI가 1-hop. multi-hop을 섞으면 "회로가 달라 보이는 게 hop 차이 때문인지 modality 차이 때문인지" 구분 불가. multi-hop은 Tier 3에서 따로.
5. **왜 Tier 1/2/3?** → 용도별 통제 수준 차등. Tier1(빡센 통제, patching용), Tier2(변수 개수 다양화, 일반화), Tier3(자유 형식, robustness).

**데이터 규모**: Tier1 1,000개(500 cf pair), Tier2 500, Tier3 500, IOI 500. 총 ~15,000 sample. **데이터는 작고, 진짜 병목은 분석 시간**(per-head patching).

# Part IV — 실험 단계별 심화

## §15. Step 2 — Grokking으로 도구 검증 (+ 삼각함수 메커니즘)

### 왜 이걸 먼저 하나 (sanity check)
본 분석 전에 "내 측정 도구(patching/ablation/Fourier)가 멀쩡한가"를 검증. **정답 회로가 이미 알려진** 과제에서 도구가 그 정답을 재현하면, 정답 모르는 코드 과제에도 신뢰하고 쓸 수 있다.

### 과제: modular addition
- `(a + b) mod 113`. 입력 `[a, b, =]`, 정답은 0~112.
- 소수 p=113은 Nanda 2023 표준. 전체 113²=12,769 pair 중 train 30%/test 70%.
- **왜 소수(prime)인가?** p가 소수면 mod 연산이 가장 깔끔한 순환군 구조(ℤ/pℤ)를 이뤄, 모델이 배우는 Fourier(주파수) 표현이 명확히 분리된다. 합성수면 약수 때문에 구조가 지저분해져 회로 분석이 어렵다. 113은 적당히 커서(12,769쌍은 다 외우기 부담 → 일반화 강제) 학습도 빠른 크기.

### 모델·학습 (※ 발표자 트랙 = `src/grokking/`)
> ⚠️ **두 트랙 공존 주의**: 이 repo엔 grokking 구현이 둘이다. 발표자(손성준) 트랙 `src/grokking/`은 **2-layer**(model.py가 "Minimal 2-layer transformer"라 명시, ablation에 L0·L1 등장), 40,000 step. 팀원(yesul.min) 트랙 `tracks/grokking/`은 **1-layer, 50,000 epoch**(Nanda 원본 충실 재현). "보고서마다 layer 수가 다르다"는 질문이 오면 → **트랙이 둘이고 나는 src/ 기준**이라고 답하면 됨.

- 2-layer transformer, d_model=128, n_heads=4(층당), d_mlp=512, **LayerNorm·bias 없음**(분석 단순화).
- 옵티마이저 **AdamW**(Adam + 분리형 weight decay — 가중치를 0쪽으로 끌어당기는 정규화가 grokking 유도의 핵심), lr=1e-3, **weight_decay=1.0**(비정상적으로 큼), **full-batch**(미니배치가 아니라 매 step에 전체 train 데이터 사용), 40,000 step. (학습 시간은 records엔 미기록 — 보고서 기준 H100 약 100초.)

### Grokking이란
> 모델이 처음엔 **암기**만(train acc↑, test acc 0)하다가, 한참 뒤 **갑자기 일반화**(test acc 0→99%)로 급전이하는 현상.

- 결과(실측, `results/analysis/grokking_full/records.jsonl`): 최종 step 40,000에서 train acc **1.000**, **test acc 0.9928**. test_acc>0.99 첫 도달은 약 **step 16,000**(이전 step 2,000에선 test 0.018 → 전형적 grokking 급전이). (※ `report.md`의 "grokking epoch 10,200"은 다른 트랙/측정 기준.)
- **weight_decay=1.0이 핵심인 이유**: 큰 weight decay가 "암기용의 크고 지저분한 가중치"에 페널티를 줘서, 모델이 **더 단순하고 일반화되는 구조(주파수 표현)** 로 이동하게 압박한다. weight decay 없으면 grokking이 잘 안 일어남.

### 모델이 덧셈을 푸는 법 — Fourier(삼각함수) 메커니즘 ★
Nanda 2023이 밝힌 놀라운 사실: 모델은 덧셈을 **외우는 게 아니라 삼각함수로 계산**한다.

1. 입력 a, b를 여러 주파수 w에 대해 `cos(wa), sin(wa)` 형태로 **임베딩**(원 위의 점처럼).
2. attention·MLP가 삼각함수 **덧셈정리**를 구현:
   `cos(w(a+b)) = cos(wa)cos(wb) − sin(wa)sin(wb)`
   → a, b의 주파수 표현을 곱·합해서 **(a+b)의 주파수 표현**을 만든다.
3. unembedding이 각 후보 c에 대해 `cos(w(a+b−c))`가 최대가 되는 c(= a+b mod p)를 고른다.

- **검증(실측 + 그림 확인)**: 학습된 임베딩 `W_E`의 Fourier mass를 주파수별로 재면, **단 2개 주파수 k=19(~730)·k=53(~490)에 mass가 압도적 집중**(나머지 54개 모드는 전부 <35). `fourier_final.png`에서 두 막대만 우뚝 솟은 게 한눈에 보인다. 즉 모델이 mod 연산을 **소수의 주파수(삼각함수)로 푼다**는 Nanda 2023 이론과 정확히 일치. (※ narrative의 "14,31,35,52"는 오류 — 실제는 19·53.)
- **ablation 실측**: MLP 제거가 치명적 — L1 MLP를 끄면 test_acc가 **0.012로 급락**(L0 MLP는 0.16), head ablation은 L1H0/L1H3 등이 상대적으로 큰 영향. → 핵심 회로가 후반 MLP에 집중.
- **결론**: 도구가 **알려진 정답 회로(주파수 기반 mod 덧셈)를 재현** → Step 3 코드 분석 결과를 신뢰할 근거 확보 ✅.

> 발표 팁: grokking은 **sanity check**라는 점을 강조. 본 발견(코드↔IOI)과 직접 관련은 없지만, "도구를 믿을 수 있다"는 토대.

- **검증**: SIH 4개(L7H3,L7H9,L8H6,L8H10)를 길이-14 프롬프트의 **14개 토큰 위치 전부**에서 패치(n=250).

| SIH Head | 절대값 최대 위치 | 값 |
|---|---|---|
| L7H3 | pos 13 (final =) | −0.093 |
| L7H9 | pos 13 | −0.019 |
| L8H6 | pos 13 | **−0.204** |
| L8H10 | pos 13 | −0.172 |

- **모든 위치에서 0 또는 음수.** 위치 문제가 아니라 **과제 구조에 SIH 메커니즘이 부재**.
- 이 비전이가 오히려 이론과 일치 → universality가 "**같은 추상 구조에서만**" 성립한다는 더 정교한 framing 가능.

## §20. 검증 B — 역할의 부호(±)까지 보존 ★★★ (가장 강한 증거)

Direct Logit Attribution(§9)으로 각 head가 정답을 밀지/깎는지 부호 측정 (n=500, 전체 head 직접 기여 합 +2.139):

| Head | IOI 역할 | 직접 기여 | z | 부호 일치 |
|---|---|---|---|---|
| L10H2 | BNMH (정답 강화) | **+1.010** | +3.3 | 일치 |
| L10H7 | NNMH (정답 억제) | **−0.305** | −1.9 | 일치 |
| L9H9 | NMH (정답 강화) | +0.303 | — | 일치 |
| L3H0 | DTH (간접 경로) | −0.018 | −0.5 | 직접효과 없음 |

- **L10H7이 결정타**: IOI에서 '정답을 일부러 깎는' Negative Name Mover인데, **코드에서도 −0.31로 정답을 똑같이 깎았다.**
- 같은 head가 단지 "켜진" 정도가 아니라, **"정답을 억제한다"는 독특한 기능이 부호까지 그대로 전이**.
- → 회로가 표면이 아니라 **기능 수준에서 보존**된다는 가장 직접적 증거.

> 발표 팁: 이 슬라이드에서 **잠시 멈추고 천천히** 강조. 본 프로젝트가 처음 정량화한 발견.

## §21. 검증 F — 회로 크기: 18%의 head가 87%의 일

- 모든 attention head를 끄면 정답신호가 0.133 감소(clean 0.182 − empty 0.049 = attention 전체 기여).
- 그런데 **IOI 26 head(전체 144의 18%)만 끄면 0.116 감소 = 전체의 87%**.

| 제거 대상 | head 수 | logit_diff 감소 | 무작위 K | 배수 |
|---|---|---|---|---|
| top3 | 3 | +0.054 | +0.031±0.070 | 1.7배 |
| top5 | 5 | +0.051 | +0.005±0.038 | ~10배 |
| top10 | 10 | +0.065 | +0.035±0.043 | 1.9배 |
| ioi26 | 26 | +0.116 | +0.046±0.054 | 2.5배 |

- → 코드 변수 바인딩 회로는 **사실상 IOI 회로의 부분집합**.
- (반대 방향 sufficiency 검증=상위만 남기고 141개 끄기는 실패 — 144개 중 141개를 끄면 모델을 정상 분포 밖으로 밀어내 잔차 스트림이 깨짐. 그래서 necessity 기반 검증이 더 신뢰됨. ← 정직한 방법론 한계.)

## §22. Cross-model — 일반화 (3모델 비교)

"GPT-2 small 하나만 그런 거 아냐?"를 막으려 두 모델 추가.

| 측면 | GPT-2 small | GPT-2 medium | Pythia-160M |
|---|---|---|---|
| 구조 | 12×12=144 | 24×16=384 | 12×12 (rotary, parallel attn+MLP) |
| Clean/Corrupt/Gap | +0.182/+0.097/+0.086 | +0.156/−0.050/+0.206 | +0.157/+0.019/+0.138 |
| Attn 전체 기여 | +0.133 | +0.136 | +0.145 |
| 최대 회복 head | L10H7(+0.49) | L17H12(+5.78) | L5H9(+1.02) |
| 우세 층(상대깊이) | L10-11(83-92%) | L17-18(71-75%) | L5-6(42-50%) |
| small과 좌표 중첩 | — | (폭 다름) | **1/10** |

- **공통(보존)**: ① 소수 head 집중 ② 그 head들이 인과적으로 중요 → 세 모델 모두.
- **차이(비보존)**: 몇 층/어느 좌표인지는 제각각. Pythia는 중간층, GPT-2 계열은 후반층. 좌표는 거의 안 겹침(무작위 기대 0.7개 대비 1개).
- Tier2 일반화도 확인: L10H2(BNMH)가 노이즈 많은 Tier2에서도 견고(ablation 감소 Tier1 +0.053 → Tier2 +0.111).

> **Pythia가 왜 좋은 대조군인가** (아키텍처 차이 — 질문 대비): GPT-2와 두 가지가 다르다. ① **Rotary positional embedding(RoPE)**: 위치를 §1처럼 '더하는' 대신, query·key 벡터를 위치에 따라 '회전'시켜 *상대 위치*를 인코딩한다. ② **Parallel attention+MLP**: attention과 MLP를 순차가 아니라 *병렬*로 계산해 residual에 합산한다. 학습 데이터(Pile)도 다르다. 이렇게 아키텍처·데이터가 다 다른데도 '소수 head 집중·인과적 필요성'이 보존된다면, 그건 GPT-2 특유의 우연이 아니라 **더 보편적 현상**이라는 강한 증거가 된다.

## §23. Hydra Effect — 예상치 못한 발견 ★★

GPT-2 medium에서 **중요 head를 껐더니 성능이 오히려 올라감**:

| 제거 | logit_diff 변화 | 무작위 K |
|---|---|---|
| 상위 3 | −0.031 (성능↑) | +0.001±0.016 |
| 상위 5 | −0.079 (성능↑) | −0.007±0.012 |
| 상위 10 | −0.121 (성능↑) | +0.017±0.044 |

**왜 일어나나 (두 메커니즘)**:
1. 상위 head 중 **정답을 억제하는 suppressor(NNMH 계열)** 가 포함 → 끄면 억제가 풀려 정답 logit이 상대적으로 ↑.
2. 큰 모델은 **백업 head가 풍부** → 주요 head를 꺼도 다른 head가 일을 이어받음(**히드라**: 머리 자르면 두 개 자람). 이게 Wang 2022가 IOI에서 보고한 Backup Name Mover hydra effect의 **scale 증폭판**.
- 무작위 head 제거는 이 효과 없음 → **통제군** 역할.

**실용적 경고**: 큰 모델에서 "head 껐더니 성능 올랐으니 쓸모없다"고 판단하면 **완전히 틀림**. redundancy 때문에 단순 ablation 위험 → **path patching** 같은 정교한 도구 필요.

## §24. 종합 — Universality 4축 분해 ★ (최종 결론)

"전이된다/안 된다" 이분법으론 설명 불가. 4축으로 쪼개면:

| 축 | 내용 | 보존? |
|---|---|---|
| 1. 기능적 집중도 | 소수 head 집중 | **세 모델 보존** |
| 2. 인과적 필요성 | 상위 head가 실제 중요 | **세 모델 보존** |
| 3. 층 단계 위치 | 작동 깊이 | 같은 계열 내 보존, 계열 간 불일치 |
| 4. head 좌표 | 정확한 층/번호 | **보존 안 됨(무작위 수준)** |

> **결론**: Universality는 **겉모습(좌표)이 아니라 기능·역할 수준에서 성립**한다. **같은 원리, 다른 해부학적 위치.**

## §26. 깊은 Q&A (난이도별, 총 18문항)

### 기초
**Q. "누가 누구를 가리키는지"가 왜 중요한가?**
A. binding(변수·대명사에 값을 묶고 나중에 참조를 푸는 것)은 **코드 실행·대명사 해석·멀티스텝 추론의 공통 바닥**입니다. 작고 정답이 명확해 회로를 정확히 짚을 수 있는 표본이고, 자연어와 코드가 같은 binding 회로를 쓰는지 보면 LLM이 표면을 넘어 추상 연산을 재사용하는지 알 수 있습니다.

**Q. Top-1 정확도 0.8%인데 신뢰 가능?**
A. 정확도가 아니라 **logit difference**(정답−방해답)를 신호로 씁니다. 최종 토큰을 못 맞혀도 정답으로 기우는 미세 신호가 잡히고, 인과 기여 측정엔 연속적 logit_diff가 0/1 정확도보다 민감합니다.

**Q. corrupt 입력이 뭔가?**
A. 정답이 바뀌도록 clean을 한 토큰만 변형한 짝(counterfactual pair)입니다. 차이를 한 군데로 국한해 특정 head의 인과 기여를 분리합니다.

**Q. residual stream이 뭔가?**
A. 각 토큰 위치를 흐르는 벡터로, 모든 head·MLP가 여기에 자기 출력을 **더합니다**. 선형 누적이라 최종 logit을 부품별 기여 합으로 분해할 수 있고, 이게 patching·attribution이 가능한 근거입니다.

### 중급
**Q. 왜 grokking부터 했나?**
A. 정답 회로가 **이미 알려진**(Nanda 2023, Fourier) modular addition으로 도구의 정확성을 먼저 검증하기 위해서입니다. 도구가 알려진 정답을 재현했으니 정답 모르는 코드 결과를 신뢰할 수 있습니다. Grokking 자체는 본 발견과 직접 관련 없는 sanity check입니다.

**Q. patching과 ablation 차이?**
A. patching은 정상값을 **이식**해 복원되는지(인과적 개입), ablation은 head를 **꺼서** 망가지는지(necessity)를 봅니다. patching이 더 직접적인 인과 증거라 주력으로 씁니다.

**Q. 발견된 head가 정말 binding 역할이라 확신하나?**
A. 세 증거를 합쳤습니다. ① patching에서 단일 head로 logit_diff 49% 복원 ② direct logit attribution으로 정답 방향 직접 기여(L10H2 +1.01, z=+3.3) ③ ablation 시 감소. 셋이 일치해야 인과 결론을 내리고, 본 분석에서 일치합니다.

**Q. "선택적 재사용" 근거가 평균뿐이면 약하지 않나?**
A. 맞아 head 단위 순위상관은 약합니다(ρ=0.106). 그래서 **클래스 평균**에 근거하고, ① SIH 위치 전수 검증(어디서도 0/음수) ② 부호 보존(L10H7 코드서도 정답 억제) ③ necessity(26 head=87%)로 **다중 검증**했습니다.

**Q. SIH가 음수인 게 노이즈 아닌가?**
A. 14개 토큰 위치 전부에서 패치해도 0 또는 음수였습니다(L8H6 −0.204). 위치 문제가 아니라 **코드엔 '중복 개체 억제'라는 과제 구조 자체가 없어** SIH가 할 일이 없는 겁니다. 비전이가 오히려 이론과 일치합니다.

**Q. cross-model에서 좌표 안 겹친 건 당연한 거 아닌가?**
A. 맞습니다, 예상된 결과입니다. 핵심은 좌표는 안 겹쳐도 **기능적 집중도·인과적 필요성은 보존**된다는 점이고, 그래서 universality를 4축으로 나눠 "기능은 universal, 해부학은 non-universal"이라 정밀화한 게 기여입니다.

### 고급
**Q. Hydra effect 설명?**
A. 큰 모델서 상위 head를 끄면 성능이 오릅니다. ① 상위에 정답 억제 head(NNMH)가 껴 끄면 억제가 풀리고 ② 백업 head가 풍부해 다른 head가 일을 이어받기 때문. 단순 ablation 해석의 위험을 보여주는 경고입니다.

**Q. top-K ablation이 성능을 높인 건 버그 아닌가?**
A. Wang 2022가 보고한 Backup Name Mover hydra와 같은 메커니즘입니다. suppressor 제거로 distractor 억제가 풀리고, 큰 모델은 백업이 강해 과보상까지 일어납니다. **무작위 K ablation은 효과 없음**이 통제군 증거라 버그가 아닙니다.

**Q. universality가 성립한다는 건가 아닌가? 결론이 뭔가?**
A. 이분법으로 답할 수 없어 **4축 분해**했습니다. 기능적 집중도·인과적 필요성은 세 모델 보존(universal), 층 위치는 계열 내만, head 좌표는 무작위(non-universal). 즉 **기능 수준 universal, 해부학 수준 non-universal**입니다.

**Q. 팀 트랙은 반대 결론(IOI 재사용 낮음)인데, 당신이 맞다는 보장은?**
A. 한쪽이 틀린 게 아닙니다. 본 트랙은 IOI와 같은 "두 후보 선택" 프롬프트 + 인과 patching을, 팀 트랙은 멀티홉 체인 + 활성도 top-K를 썼습니다. 개입과 관찰은 다른 head를 부각합니다. 이건 "**측정 방법이 회로 결론을 좌우한다**"는 메타 교훈이고, 두 결과를 함께 제시하는 게 정직합니다.

**Q. GPT-4 같은 큰 모델에도 적용되나?**
A. compute 한계로 검증 못 했습니다. 다만 small→medium→Pythia에서 기능적 보존이 일관됐고 hydra가 scale에 강해진 걸 보면 큰 모델일수록 redundancy가 커질 것으로 추정합니다. 단정은 안 합니다.

**Q. 왜 GPT-2 small을 주 모델로?**
A. Wang 2022의 IOI 회로 reference가 GPT-2 small에 있어 직접 비교 가능하기 때문입니다. 더 큰 GPT-2 medium·Pythia로 재현해 scale·아키텍처 효과를 봤습니다.

**Q. 보고서마다 grokking 모델이 1-layer / 2-layer로 다르던데?**
A. 트랙이 둘입니다. 제 트랙(`src/grokking`)은 회로 분석 편의를 위해 **2-layer, 40k step**을 썼고(L0·L1 두 레이어를 ablation으로 분석), 팀원 트랙(`tracks/grokking`)은 Nanda 2023 원본을 **1-layer, 50k epoch**로 충실히 재현했습니다. 제 발표 수치는 모두 src/ 기준이고, 둘 다 grokking과 Fourier 회로를 정상 재현했습니다.

**Q. 실용적 함의가 뭔가?**
A. ① 코드와 자연어가 출력 회로를 공유하므로 **코드 fine-tuning이 자연어 정렬에 영향**을 줄 수 있다 — "코드만 따로 안전 점검"이 불충분. ② 큰 모델 해석에 단순 ablation은 위험(hydra) — 정교한 인과 도구 필요.

**Q. 1주일 만에 어떻게 이만큼?**
A. H100 1장 + 효율적 코드. grokking 학습 101초, 모델당 patching 15분, cross-model 70분. 모든 결과는 재현 가능합니다.

## §27. 용어 빠른 사전

## §30. 코드 근거 부록 — 질문받으면 여기로 연결

> 발표 중 "그 수치가 코드 어디서 나오나요?"를 받으면, 아래처럼 답하면 된다. 핵심은 **데이터 생성 → baseline → patching → IOI 비교 → 부호/ablation 검증 → grokking sanity check** 순서다.

### 1. 데이터 설계 근거
- 파일: `data/var_binding.py`
- 핵심 함수: `gen_tier1_pair`, `_make_record`, `_next_token_for_answer`, `_binding_source_token_pos`
- 바로 보여줄 코드:
```python
def gen_tier1_pair(n_vars: int, rng: random.Random, pair_idx: int):
    """Generate one counterfactual pair (clean + corrupted).

    Clean and corrupted prompts differ in exactly one token (the source var
    in the binding line), so token positions stay aligned.
    """
    names = rng.sample(SINGLE_LETTER_POOL, n_vars)
    values = {v: rng.choice(ANSWER_VALUES) for v in names}

    target = names[-1]
    candidates = [v for v in names if v != target]
    src_clean, src_corrupt = rng.sample(candidates, 2)

    prefix = "; ".join(f"{v}={values[v]}" for v in names if v != target)
    clean = f"{prefix}; {target}={src_clean}; {target}="
    corrupt = f"{prefix}; {target}={src_corrupt}; {target}="
```
- 말할 포인트:
  - Tier 1 clean/corrupt pair는 `gen_tier1_pair()`가 만든다. clean과 corrupt는 binding line의 source 변수만 바뀌므로 activation patching에서 token position이 정렬된다.
  - `_next_token_for_answer()`가 GPT-2 BPE 기준으로 정답 숫자가 **다음 한 토큰**인지 검사한다. 그래서 발표에서 말한 "정답값 1~9, single-token constraint"가 구현으로 보장된다.
  - `_binding_source_token_pos()`가 binding line 안 source 변수 위치를 기록한다. position patching이나 SIH 위치 검증에서 이 metadata를 쓴다.
- 결과물: `datasets/var_binding_tier1.jsonl`, `datasets/var_binding_tier2.jsonl`, `datasets/var_binding_tier3.jsonl`

### 2. baseline logit_diff
- 파일: `src/binding/baseline.py`
- 핵심 함수: `logit_diff`, `load_pairs`, `main`
- 바로 보여줄 코드:
```python
def logit_diff(logits_last, answer_id, distractor_ids):
    """logit_diff = logit(answer) - mean(logit(distractors))."""
    ans = logits_last[answer_id]
    dist = logits_last[distractor_ids].mean()
    return (ans - dist).item()
```
- 말할 포인트:
  - `logit_diff = logit(answer) - mean(logit(distractors))`가 코드 그대로 들어 있다.
  - clean/corrupt pair를 둘 다 GPT-2 small에 넣고 평균 logit_diff, top-1 accuracy, clean-corrupt gap을 저장한다.
  - 발표 수치 `Clean +0.182`, `Corrupt +0.097`, `Gap +0.086`, `Top-1 0.8%`는 이 단계의 결과다.
- 결과물: `results/binding_baseline.json`

### 3. per-head activation patching
- 파일: `src/binding/patching.py`
- 핵심 hook: `blocks.{L}.attn.hook_z`
- 바로 보여줄 코드:
```python
clean_z = clean_cache[f"blocks.{L}.attn.hook_z"]    # [1, T, H, Dh]

def hook_fn(z, hook, _L=L, _H=H, _cz=clean_z):
    z[:, :, _H, :] = _cz[:, :, _H, :]
    return z

patched = model.run_with_hooks(
    corr_tok,
    fwd_hooks=[(f"blocks.{L}.attn.hook_z", hook_fn)],
)
patched_ld = logit_diff(patched[0, -1], ans_id, dist_ids)
effects[i, L, H] = (patched_ld - corr_ld) / gap
```
- 말할 포인트:
  - clean run에서 각 layer/head의 `hook_z`를 cache한다.
  - corrupt run을 돌릴 때 조사 대상 head 하나의 `z[:, :, H, :]`만 clean activation으로 바꿔 끼운다.
  - recovery는 코드 주석 그대로 `(patched_ld - corrupt_ld) / (clean_ld - corrupt_ld)`다.
  - 이 sweep이 12 layers × 12 heads = 144개 head 전체에 대해 실행된다.
- 결과물: `results/binding_patching/head_effects.npy`, `results/binding_patching/top_heads.json`, `results/binding_patching/head_mean.png`

- 핵심 상수: `IOI_HEADS`
- 바로 보여줄 코드:

```python
    frac = sum(1 for h in topK if h in ioi_set) / K
    random = 26 / 144
    print(f"K={K}: frac={frac:.2%}, enrichment x{frac/random:.2f}")
```
- 말할 포인트:
  - Wang 2022의 26개 IOI head taxonomy가 `IOI_HEADS`에 명시돼 있다: DTH/PTH/IH/SIH/NMH/BNMH/NNMH.
  - patching 평균 recovery의 top-K와 `IOI_HEADS`의 overlap을 계산한다.
  - 클래스별 평균 recovery와 Spearman/Pearson rank correlation도 여기서 계산한다.
  - 발표 수치 `Top5 4/5`, `K=5 enrichment ×4.4`, `Spearman ρ=0.106`은 이 비교 코드에서 나온다.
- 결과물: `results/binding_compare/universality_report.json`, `results/binding_compare/code_vs_ioi.png`, `results/binding_compare/universality_summary.png`

### 5. 부호 보존: direct logit attribution
- 파일: `src/binding/logit_attribution.py`
- 핵심 hook/cache: `model.set_use_attn_result(True)`, `cache["result", L]`
- 바로 보여줄 코드:
```python
model.set_use_attn_result(True)
W_U = model.W_U

dist_mean = W_U[:, dist_ids].mean(dim=1)
direction = W_U[:, ans_id] - dist_mean

_, cache = model.run_with_cache(tok)
result = cache["result", L][0, T - 1]     # [n_heads, d_model]
attr = (result @ direction).cpu().numpy() # [n_heads]
per_head_attr[i, L, :] = attr
```
- 말할 포인트:
  - patching은 "중요한가"를, direct logit attribution은 "정답을 밀었나/깎았나"를 본다.
  - 각 head의 final position output을 `W_U[:, answer] - mean(W_U[:, distractors])` 방향에 projection한다.
  - L10H2는 positive, L10H7은 negative로 나와서 IOI의 BNMH/NNMH 부호가 코드에서도 보존됐다는 핵심 근거가 된다.
- 결과물: `results/binding_logit_attr/summary.json`, `results/binding_logit_attr/per_head_attr.npy`, `results/binding_logit_attr/logit_attr_heatmap.png`

### 6. 회로 크기와 necessity ablation
- 파일: `src/binding/minimal_circuit.py`
- 핵심 함수: `run_remove`, `run_set`, `make_remove_hook`, `make_keep_hook`
- 바로 보여줄 코드:
```python
def make_remove_hook(remove_set_by_layer, L):
    """Zero only the heads at layer L in remove_set_by_layer[L]."""
    remove_h = remove_set_by_layer.get(L, set())

    def hook(z, hook):
        for H in remove_h:
            z[:, :, H, :] = 0
        return z
    return hook

hooks = [(f"blocks.{L}.attn.hook_z", make_remove_hook(rem_by_layer, L))
         for L in range(n_layers) if rem_by_layer[L]]
logits = model.run_with_hooks(toks, fwd_hooks=hooks)
```
- 말할 포인트:
  - `run_remove()`는 특정 head set만 제거하고 나머지는 둔다. 이것이 발표의 necessity test다.
  - `IOI26`은 `compare_ioi.py`의 `IOI_HEADS`에서 가져온 26개 head 전체다.
  - all-attention contribution과 IOI26 ablation drop을 비교해서 "전체 attention 기여의 87%"라는 결론을 만든다.
  - keep-only sufficiency는 실패했다고 문서에 적은 그대로다. 141개 head를 한꺼번에 끄면 분포 밖 개입이 커져 해석이 약해진다.
- 결과물: `results/binding_minimal_circuit/results.json`, `results/binding_minimal_circuit/necessity.png`, `results/binding_minimal_circuit/sufficiency.png`

### 7. grokking sanity check

- 핵심 구조:

  - `src/grokking/analysis.py`: Fourier score, attention/MLP ablation 분석.
- 바로 보여줄 코드:
```python
model = GrokkingTransformer(
    vocab=vocab, n_ctx=xtr.shape[1],
    d_model=args.d_model, n_heads=args.n_heads,
    d_mlp=args.d_mlp, n_layers=args.n_layers,

opt = torch.optim.AdamW(
    model.parameters(), lr=args.lr, weight_decay=args.wd, betas=(0.9, 0.98)

opt.step()
```
